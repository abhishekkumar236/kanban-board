6
  1. 1Filters live in the URL. Read them from searchParams. A copied link then opens the exact same view, and the browser back button undoes a filter change.
  2. 2Presence. Shows who else has this board open. It comes from your WebSocket server, which is the part you already know how to build.
  3. 3Dragging. The card follows the pointer, and the dashed slot shows where it will land. Use the dnd-kit library; don't build dragging from scratch.
  4. 4Optimistic update. The card moves the moment it's dropped and shows "Saving…" until the server confirms. If the save fails, it moves back (see 05 → Save failed).
  5. 5Live update. A teammate's change arrives over the socket. Highlight the card for a few seconds so people notice it moved.
  6. 6Toast. Says what changed and who did it. It closes on its own after about 5 seconds.

Drag and drop cards between columns

1

Users should be able to move a card to another column by dragging it. The card moves straight away and we save in the background.

Acceptance criteria

  • Card follows the pointer while dragging
  • Dashed slot shows where it will land
  • Status saves after drop (optimistic)
  • If saving fails, card moves back and an error toast shows
  • Works with the keyboard (space to pick up, arrows to move)

Before you code

Take 15 minutes with paper and answer these before you write any code:

  1. Draw boxes around this board and name each one. Those boxes are your components. Which ones repeat?
  2. Which components need "use client"? Why can't the board itself be a Server Component?
  3. Once the issues are fetched, where do they live so the board, the issue panel and the command palette all see the same data?
  4. When a WebSocket event says "LL-14 moved to In Review", what is the smallest thing you need to update?

      └─ Column       × 5, one per status

   IssuePanel         its own route, shown over the board
   NewIssueDialog · CommandPalette · Toaster

Shared pieces built once, used everywhere:
   StatusIcon · PriorityIcon · LabelChip · Avatar · PropertyDropdown

Answers in short:
   2. Board needs onClick, drag events and live updates, which only run in the browser.
   3. In one client-side cache (TanStack Query), keyed by team + filters.
   4. One issue's status in that cache. Not a refetch of the whole board.
